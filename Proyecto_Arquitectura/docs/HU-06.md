# HU-06 — Expediente técnico y búsqueda

## Alcance y decisiones

Esta entrega implementa solo HU-06. La carpeta `modules/technical_record` es un
módulo vertical de la historia dentro del monolito; no se crea una carpeta `HU-07`
ni tablas para funciones futuras.

El SAD vigente fija FastAPI, SQLAlchemy, Alembic y MySQL 8.4/MariaDB. Un documento
auxiliar anterior recomienda PostgreSQL; se prioriza el SAD. La consulta se normaliza
con `strip().upper()`, preservando guiones y espacios internos, y busca en una columna
única e indexada. Los campos de batería/controlador son descriptivos y opcionales:
voltaje, amperaje, capacidad, tipo de celdas, notas técnicas, modelo/firmware/modificaciones.
Se almacenan como texto para no imponer unidades, rangos ni campos no confirmados.

La configuración asociada al vehículo representa la configuración actual. Las
reparaciones son registros históricos 1:N; no se afirma que contengan una fotografía
histórica de batería/controlador. La decisión de conservar snapshots históricos debe
validarse antes de ampliar el modelo. Las observaciones son texto plano (máximo 2.000
caracteres), no HTML enriquecido; el frontend las inserta con `textContent`, por lo que
las etiquetas enviadas se muestran literalmente y no se ejecutan.

las fechas de observaciones se generan en UTC.

## API

Base `/api/v1`, JSON `snake_case`; la documentación OpenAPI se genera en `/docs`.

| Método y ruta | Entrada/salida | Permiso y errores |
|---|---|---|
| `POST /auth/token` | Usuario/contraseña → JWT Bearer con expiración | Credenciales incorrectas: 401 genérico |
| `GET /technical-records/by-serial/{serial_number}` | Serie/chasis → vehículo, configuración actual, historial y observaciones | Mecánico/administrador; 401 sin sesión, 403 rol no permitido, 404 «Vehículo no encontrado» |
| `POST /technical-records/{vehicle_id}/observations` | `{ "content": "..." }` → observación registrada | Mecánico/administrador; 401/403/404/422 |
| `PUT /technical-records/{vehicle_id}/specifications` | Batería y controlador (cada objeto puede ser `null`) → expediente actualizado | Mecánico/administrador; 401/403/404/422 |

El servidor vuelve a comprobar usuario activo/rol en cada operación protegida. Las
contraseñas se almacenan como Argon2id; el JWT HS256 lleva expiración y nunca se guarda
en la base. Ninguna ruta de este alcance consulta por documento ni expone una interfaz
pública.

`PUT` reemplaza la configuración actual de batería y controlador en una transacción;
no altera las reparaciones históricas. Ambos objetos deben enviarse y pueden ser `null`
si el vehículo no tiene esa configuración registrada.

## Datos de demostración y prueba de rendimiento

`scripts/seed_demo.py` inserta datos ficticios de forma repetible y solicita por consola
una cuenta local; no versiona contraseñas en texto plano. `scripts/benchmark_search.py`
genera 5.000 vehículos y 50.000 reparaciones en una base SQLite temporal, mide el
tiempo de búsqueda y consulta del historial de un vehículo, e informa el resultado
real y la meta <2 s. Este benchmark es evidencia de la estrategia de índice, no una
medición de MySQL ni una garantía para otros equipos.

Las pruebas de API cubren autenticación, autorización, búsqueda, ausencia de historial,
historial múltiple, lectura/escritura y validación de especificaciones y observaciones
con payload XSS como texto inerte. La migración desde base vacía se valida en SQLite y
en MySQL 8.4; `alembic check` confirma que el esquema MySQL coincide con los modelos.

Medición local (12-oct-2026): SQLite, 5.000 vehículos y 50.000 reparaciones, 20 búsquedas
de una serie con 10 reparaciones; mediana **1,905 ms**, p95 **2,410 ms**. La meta
documentada de menos de 2 s se cumple en esta medición SQLite; no es una medición de
MySQL ni una garantía para otros equipos. Suite: 20 pruebas y 96 % de cobertura del
módulo técnico.
